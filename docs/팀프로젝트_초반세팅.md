# SEWS 팀프로젝트 초반 세팅

ICU 패혈증 조기 경보 시스템(SEWS)을 **15주 PBL**로 돌리기 위해, 코딩 시작 전에 팀이 맞춰야 하는 것들.

원본 기획: [프로젝트 소개.md](./프로젝트%20소개.md)

---

## 결론부터

**`BackEnd` / `FrontEnd` 두 폴더만 나누면 안 된다.**

이 과제는 웹앱이 아니라 **데이터 → 전처리 → 학습 → 서빙 → 대시보드 → MLOps** 파이프라인이다. 프론트/백만 쪼개면:

- 전처리·SOFA·라벨링·특징 추출이 백엔드에 섞이거나, 어디에도 안 들어간다.
- `.parquet` / `.pkl` / 노트북 / MLflow 로그가 Git 충돌과 용량 사고를 낸다.
- Streamlit이 모델을 직접 로드하기 쉬워져, 기획서의 모듈 분리가 깨진다.

**한 개의 Git 모노레포**로 두고, 역할은 폴더로 나눈다.

| 역할 | 폴더 | BackEnd/FrontEnd로 치면 |
| --- | --- | --- |
| 데이터 파이프라인 | `src/preprocess`, `src/features` | 둘 다 아님 |
| 학습·평가 | `src/train`, `src/evaluate` | 둘 다 아님 |
| 추론 API | `api/` | BackEnd |
| 임상 대시보드 | `dashboard/` | FrontEnd (Streamlit) |
| 실행 환경 | `docker/`, `configs/` | 인프라 |
| 산출 문서 | `docs/`, `notebooks/` | 문서 |

프론트/백 **동시 개발**은 폴더 이름이 아니라 **JSON 계약**으로 한다.

## 1. 저장소 한 개, 폴더로 나눈다

현재 `Z:\SEWS` 골격:

```
SEWS/
├── README.md
├── .gitignore
├── docs/                  # 기획서, 초반세팅, 이후 리포트
├── notebooks/             # EDA 전용. 재현 로직은 여기 남기지 말 것
├── data/
│   ├── raw/               # PhysioNet 원본 (Git 제외)
│   ├── interim/           # 병합·정렬 중간물 (Git 제외)
│   └── processed/         # 특징 parquet (Git 제외)
├── src/
│   ├── preprocess/        # 로딩, 결측, SOFA/qSOFA
│   ├── features/          # Sliding Window 50+ 특징
│   ├── train/             # XGBoost / LSTM / Ensemble / Calibration
│   ├── evaluate/          # AUROC, AUPRC, Brier, Utility
│   └── common/            # 경로, 시드, 로깅
├── api/                   # FastAPI: /health /predict /predict_batch /explain
├── dashboard/             # Streamlit. api만 호출. 모델 로드 금지
├── models/                # .pkl / .pt (Git 제외)
├── configs/               # 윈도우 길이, 임계값, 경로
├── docker/                # Dockerfile들
├── tests/                 # SOFA, 라벨, JSON 스키마, 누수 가드
└── scripts/               # 다운로드·학습·서빙 헬퍼
```

### 왜 레포를 쪼개지 않는가

- 팀이 소규모(역할 5개)이고 기간이 15주다.
- API JSON 스키마, 특징 컬럼, 임계값 0.5/0.75가 **같은 커밋**에 있어야 회귀가 보인다.
- 분리 레포는 권한·CI·이슈가 세 배로 늘고, 학기 과제에서 이득이 거의 없다.

나중에 진짜로 커지면 그때 `api`, `dashboard`를 패키지로 분리해도 늦지 않다.

## 2. Git은 이렇게 판다

로컬이 `Z:\SEWS`라면 (PowerShell):

```powershell
cd Z:\SEWS
git init
git add README.md .gitignore docs
git commit -m "chore: 저장소 초기화, 기획서와 초반 세팅 문서"
```

데이터·모델은 커밋하지 않는다. `.gitignore`가 이미 막아 두었다.

### 원격

1. GitHub 조직 또는 대표 계정에 **private** 저장소 `SEWS` 생성.
2. 팀원 전원 Collaborator (Write).
3. PhysioNet DUA 때문에 **원본 데이터 업로드 금지**. 공개로 바꾸지 말 것.

```powershell
git remote add origin https://github.com/<ORG>/SEWS.git
git branch -M main
git push -u origin main
```

### 브랜치

| 브랜치 | 용도 |
| --- | --- |
| `main` | 제출·데모 가능한 상태만. 직접 커밋 금지 |
| `develop` | 통합 브랜치. PR 머지 대상 |
| `feat/<이니셜>-<주제>` | 작업 단위. 예: `feat/km-sofa`, `feat/jh-api-health` |
| `fix/<이니셜>-<이슈>` | 버그 |

규칙:

- `main` ← `develop`만 머지. 마일스톤 때.
- PR 없으면 `develop`에 푸시하지 않는다.
- 한 PR = 한 주제. “전처리+LSTM+대시보드” 금지.
- 머지 전 최소 1명 리뷰. 작성자 셀프머지 금지.
- 시드·스키마·임계값 변경은 PR 본문에 **왜**를 적는다.

### 커밋 메시지

```
feat: SOFA 6요소 계산 모듈
fix: 환자ID 분리 시 시계열 누수
docs: setA/setB 병합 전략
chore: .gitignore에 mlruns 추가
test: qSOFA 단위 테스트
```

한글/영어 섞여도 된다. 제목은 명령형, 50자 안쪽.

### 절대 Git에 올리지 말 것

- `data/raw`, `data/interim`, `data/processed`
- `models/*.pkl`, `*.pt`, `*.parquet`
- `.env`, PhysioNet 계정, API 키
- `mlruns/` 대용량 아티팩트

데이터는 **NAS / 구글드라이브 / 팀 공유 폴더**에 `SEWS/data`로 두고, 로컬은 심볼릭 링크 또는 `configs/paths.yaml`로 가리킨다.

## 3. 코딩 전에 팀이 확정할 것 (1주차)

기획서 T1~T3가 여기 해당한다. 이게 끝나기 전에 모델 코드를 짜면 전부 다시 짠다.

### 3.1 사람

| 역할 | 이름 | Learning Issue | 주 산출물 |
| --- | --- | --- | --- |
| 데이터 엔지니어 | | #1 #2 #3 | EDA, SOFA, 라벨, split |
| ML 엔지니어 A | | #4 #5 #6 | Utility, 불균형, AUPRC |
| ML 엔지니어 B | | #7 #9 #10 | Calibration, LSTM, Ensemble |
| 백엔드 | | #11 #12 #13 | FastAPI, SHAP, 스키마 |
| 프론트/MLOps | | #14 #15 #16 #17 | Streamlit, Docker, MLflow, 경보 |

빈칸을 첫 미팅에서 채운다. 한 사람이 두 역할을 겸하면 **백엔드+프론트** 또는 **ML A+B**만 겸한다. 데이터와 서빙을 한 사람이 다 가져가면 병목이다.

### 3.2 도구 (계정·권한)

| 도구 | 용도 | 누가 만드나 |
| --- | --- | --- |
| GitHub private repo | 코드 | 리더 1명, 전원 write |
| Notion / 이슈 보드 | 주간 세미나, T1~T21 | 전원 편집 |
| PhysioNet 계정 | 데이터 다운로드 | **전원 DUA 서명** |
| Python 3.11 | 런타임 | 로컬 통일 |
| Docker Desktop | 이후 Compose | 로컬 설치만 1주차 |
| MLflow | 실험 기록 | Phase 3. 지금은 폴더만 |

에디터는 자유. 포맷터는 하나로: `ruff` + 노트북은 `nb-clean` 권장.

### 3.3 데이터 계약 (코드보다 먼저)

`docs/data-contract.md`를 1주차에 초안으로 만든다.

필수 합의:

1. 시간 단위: 1시간 그리드인가, 원본 irregular인가.
2. Observation window **24h**, prediction horizon **6h** — 라벨이 어느 시각에 붙는지 그림으로.
3. 환자 ID로만 Train/Val/Test 분리. 행 단위 split 금지 (누수).
4. 시드 고정 값 (예: `42`)과 split 비율.
5. setA vs setB: 학습/외부검증 역할.
6. 결측: 측정 여부 플래그(missingness indicator)를 기본 특징으로 넣을지.

### 3.4 API JSON 계약 (프론트/백 동시 개발의 실제 방법)

`docs/api-contract.md` + `configs/api-schema.json`.

엔드포인트는 기획서 그대로 4개:

| Method | Path | 역할 |
| --- | --- | --- |
| GET | `/health` | 모델 로드 여부, 버전 |
| POST | `/predict` | 단건 확률, 경보 단계 |
| POST | `/predict_batch` | 리스트 |
| POST | `/explain` | SHAP top features |

경보:

- `normal`: p < 0.50
- `warning`: 0.50 ≤ p < 0.75
- `alert`: p ≥ 0.75

백엔드가 없어도 프론트는 Mock 서버(고정 JSON)로 UI를 진행한다. 이게 “팀 병목” 리스크 대응이다.

### 3.5 성능·제약 (처음부터 README에 박아 두기)

| 지표 | 목표 |
| --- | --- |
| AUROC | ≥ 0.82 |
| AUPRC | ≥ 0.40 |
| Brier | ≤ 0.15 |
| 추론 지연 | 평균·P95 측정, 200ms 초과 시 캐시/ONNX |

## 6. 폴더별 소유권 (충돌 줄이기)

같은 파일을 두 사람이 동시에 고치지 않게:

| 경로 | 기본 소유 |
| --- | --- |
| `src/preprocess`, `src/features`, `notebooks/` | 데이터 엔지니어 |
| `src/train`, `src/evaluate`, `models/` | ML A / ML B (파일 단위로 나눔) |
| `api/` | 백엔드 |
| `dashboard/` | 프론트/MLOps |
| `docker/`, `configs/` | 프론트/MLOps + 백엔드 리뷰 |
| `docs/api-contract.md` | 백엔드 작성, 전원 승인 |
| `docs/data-contract.md` | 데이터 엔지니어 작성, ML 승인 |

공유 파일(`configs/thresholds.yaml` 등)은 이슈 없이 고치지 않는다.

## 7. 로컬 환경 최소선

```powershell
cd Z:\SEWS
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -U pip
```

의존성은 나중에 `requirements.txt`를 **서비스별로** 둘 수 있다.

- `src` + 학습: `requirements-ml.txt`
- `api`: `requirements-api.txt`
- `dashboard`: `requirements-dash.txt`

처음엔 파일 하나로 시작해도 된다. 쪼개는 시점은 Docker 들어갈 때.

시드·경로만 있는 `configs/default.yaml` 초안:

```yaml
seed: 42
window_hours: 24
horizon_hours: 6
thresholds:
  warning: 0.50
  alert: 0.75
paths:
  raw: data/raw
  processed: data/processed
  models: models
```

## 8. 하지 말 것

1. 원본 ICU 데이터를 GitHub에 푸시.
2. 노트북에 전처리 200줄을 쌓고 `src/`로 안 옮김.

5. 팀원마다 Python 3.9 / 3.12 혼용.
6. `BackEnd`, `FrontEnd` 폴더를 새로 만들어 현재 구조를 다시 접기.
