팀프로젝트 초반 세팅

코딩 전에 맞출 Git, 폴더, 계약, 1주차 체크리스트. 원본 기획서는 docs/프로젝트 소개.md.

결론: 초기 세팅을 BackEnd / FrontEnd 두 폴더로만 나누면 안 된다. 이 과제는 웹앱이 아니라 데이터 → 전처리 → 학습 → FastAPI → Streamlit → Docker 파이프라인이다. Git 저장소는 하나(모노레포)로 두고 역할은 폴더로 나눈다.
폴더 Git 1주차 계약 체크리스트 운영 다음 미팅

1. 왜 BackEnd / FrontEnd만으로는 부족한가

기획서 모듈은 src/preprocess, src/train, api/, dashboard/, docker/, configs/다. 프론트/백만 만들면:

  • 전처리·SOFA·라벨링·특징 추출이 백엔드에 섞이거나 갈 곳이 없다.
  • .parquet / 모델 가중치 / 노트북 / MLflow 로그가 Git 용량·충돌 사고를 낸다.
  • Streamlit이 모델을 직접 로드하기 쉬워져 API 경계가 무너진다.
역할폴더BackEnd/FrontEnd로 치면
데이터 파이프라인src/preprocess, src/features둘 다 아님
학습·평가src/train, src/evaluate둘 다 아님
추론 APIapi/BackEnd
임상 대시보드dashboard/FrontEnd (Streamlit)
실행 환경docker/, configs/인프라
문서docs/, notebooks/문서

프론트/백 동시 개발은 폴더 이름이 아니라 JSON 계약으로 한다.

현재 Z:\SEWS 골격

SEWS/
├── README.md
├── .gitignore
├── docs/                  # 기획서, 초반세팅, 이후 리포트
├── notebooks/             # EDA만. 재현 로직은 src/로
├── data/raw|interim|processed/   # Git 제외
├── src/preprocess|features|train|evaluate|common
├── api/                   # FastAPI 4 엔드포인트
├── dashboard/             # Streamlit. 모델 로드 금지
├── models/                # Git 제외
├── configs/ docker/ tests/ scripts/

레포를 api/dash/ml 셋으로 쪼개지 않는다. 소규모 15주 과제에서 스키마·임계값·특징 컬럼이 같은 커밋에 있어야 회귀가 보인다.

2. Git은 이렇게 판다

저장소는 Z:\SEWS 한 개. 드라이브 루트 Z:\에 이미 .git이 있어도 무시하고, 프로젝트 폴더 안에서 새로 초기화한다.

cd Z:\SEWS
git init
git add README.md .gitignore docs
git commit -m "chore: 저장소 초기화, 기획서와 초반 세팅 문서"

원격

  1. GitHub에 private 저장소 SEWS 생성.
  2. 팀원 전원 Collaborator (Write).
  3. PhysioNet DUA 때문에 원본 데이터 업로드 금지. 공개 전환 금지.
git remote add origin https://github.com/<ORG>/SEWS.git
git branch -M main
git push -u origin main
브랜치용도
main제출·데모 가능한 상태만. 직접 커밋 금지
develop통합 브랜치. PR 머지 대상
feat/이니셜-주제예: feat/km-sofa, feat/jh-api-health
fix/이니셜-이슈버그
  • main ← develop만, 마일스톤 때.
  • PR 없이 develop 푸시 금지. 한 PR = 한 주제.
  • 머지 전 1명 리뷰. 작성자 셀프머지 금지.

커밋 메시지

feat: SOFA 6요소 계산 모듈
fix: 환자ID 분리 시 시계열 누수
docs: setA/setB 병합 전략
chore: .gitignore에 mlruns 추가
test: qSOFA 단위 테스트

절대 Git에 올리지 말 것

  • data/raw, interim, processed
  • models/*.pkl, *.pt, *.parquet
  • .env, PhysioNet 계정, API 키, mlruns/

데이터는 NAS/드라이브 공유 후 로컬은 configs/paths.yaml로 가리킨다.
