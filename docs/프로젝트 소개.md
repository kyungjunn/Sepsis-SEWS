# ICU 패혈증 조기 경보 시스템 — PBL 기획서

(Intensive Care Unit : 중환자실)

---

## ① 과제 분석 — 우리가 해결해야 할 문제는?

**핵심 문제**

- ICU 환자의 패혈증 **6시간 전 조기 탐지**
- 늦은 인지 → 항생제 지연 → 사망률 급증
- 오경보 남발 → **Alert Fatigue(알림 피로)**→ 시스템 무력화

**사용자**

- 1차: ICU 의료진(중환자 전담의, 간호사) → 위험도·근거 확인
- 2차: 병원 IT/MLOps 담당 → 배포·운영

**최종 결과물**

- 전처리·학습 파이프라인 (`.parquet`, `.pkl`/`.pt`)
- FastAPI 추론 서버 (`/health`, `/predict`, `/predict_batch`, `/explain`)
- Streamlit 임상 대시보드 (신호등, SHAP, Calibration)
- Docker Compose 원클릭 실행 + 기술 리포트 + MLflow 로그

**한 문장 정의**

> PhysioNet 2019 ICU 시계열 데이터로 **24시간 관찰 → 6시간 후 패혈증 발생을 예측**하고, 보정된 확률과 SHAP 근거를 API·대시보드로 제공하는 **End-to-End 임상 의사결정 지원 시스템**을 구축한다.
>

## ② 문제 분해 — 무엇을 해야 하는가?

**선후관계 (파이프라인)**

```
데이터 확보/DUA
   ↓
EDA (setA vs setB 분포·결측률 비교)
   ↓
전처리 (병합·정렬·결측치·SOFA/qSOFA 계산)
   ↓
라벨링 (Sepsis-3, SOFA +2점) + 환자ID 단위 분리
   ↓
특징 추출 (Sliding Window, 50개 이상)
   ↓
모델 학습 (XGBoost → LSTM → Ensemble) + Group 5-Fold CV
   ↓
	Calibration (Platt/Isotonic) + 임계값 결정
   ↓
평가 (AUROC/AUPRC/Utility/Brier)
   ↓
서빙 (FastAPI + SHAP) ─→ 대시보드 (Streamlit)
   ↓
MLOps (Docker Compose, MLflow, 문서화)
```

**병렬 가능 구간**

- 전처리·학습 ‖ API 스켈레톤 개발 ‖ 대시보드 UI 목업
- 계약(JSON 스키마) **먼저 확정** → 프론트/백 동시 진행

**모듈 분리**

| 모듈 | 책임 |
| --- | --- |
| `src/preprocess` | 로딩, 결측치, SOFA, 특징 |
| `src/train` | 모델, CV, Calibration, 평가 |
| `api/` | FastAPI 추론, SHAP |
| `dashboard/` | Streamlit UI (모델 직접 로드 금지) |
| `docker/`, `configs/` | 실행 환경, 설정 |

## ⑤ 실행계획 — 어떤 순서로 진행할 것인가?

### Phase 1. 기반 구축 (1~3주)

- T1. DUA 동의, 데이터 다운로드, Git/Notion 세팅
- T2. EDA (setA/setB 결측률·분포·라벨 비율 비교) → 병합 전략 문서화
- T3. 데이터 스키마 & JSON 계약 확정

### Phase 2. 데이터 파이프라인 (4~6주)

- T4. 결측치 처리 (FFill/Interp/KNN 비교 → 근거 문서화)
- T5. SOFA / qSOFA 계산 모듈 + 단위 테스트
- T6. Sepsis-3 라벨링, 환자ID 기반 Train/Val/Test 분리 (시드 고정)
- T7. Sliding Window 특징 추출 (50개 이상) → `.parquet`

### Phase 3. 모델링 (7~10주)

- T8. XGBoost Baseline + Group 5-Fold CV
- T9. LSTM/GRU + Class Weight / Focal Loss
- T10. Ensemble (Soft Voting / Stacking)
- T11. MLflow 하이퍼파라미터 튜닝 기록
- T12. Calibration (Platt/Isotonic) + Brier/ECE
- T13. Utility Score 구현, 임계값 선정 + 혼동행렬

### Phase 4. 시스템 개발 (9~13주, Phase 3와 일부 병렬)

- T14. FastAPI 4개 엔드포인트 + Pydantic + Singleton 로딩
- T15. SHAP `/explain` 구현, 지연 시간 측정 (평균/P95)
- T16. Streamlit 리스트뷰·상세뷰·SOFA 막대·SHAP·Calibration
- T17. 2단계 경보(Warning 0.5~0.75 / Alert ≥0.75)

### Phase 5. 통합 & 마무리 (14~15주)

- T18. Docker Compose 원클릭 실행 검증
- T19. 기술 리포트 7개 목차 작성
- T20. README (아키텍처 다이어그램, 실행법, 성능표, 팀 역할)
- T21. (보너스) GitHub Actions CI, Locust 부하 테스트, ONNX
