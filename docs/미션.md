# 1. 미션 소개

패혈증(Sepsis)은 감염에 대한 신체의 비정상적 반응으로, ICU 환자 사망 원인의 30~50%를 차지한다. 현업에서는 활력징후와 검사실 데이터를 기반으로 패혈증 발생을 6시간 전에 예측하여 조기 항생제 투여를 가능하게 하는 AI 시스템이 FDA 승인을 받아 실제 병원에서 운영되고 있다.
이 미션에서는 PhysioNet Challenge 2019 데이터셋을 활용하여 패혈증 조기 경보 시스템(SEWS: Sepsis Early Warning System)을 구축한다. 시계열 데이터 전처리 파이프라인, XGBoost와 LSTM 기반 예측 모델, FastAPI 추론 서버, Streamlit 임상 대시보드를 개발하여 End-to-End AI 의료 시스템을 완성한다.
이 과정에서 Sepsis-3 진단 기준과 SOFA 점수 계산, Observation Window와 Prediction Horizon 개념, 클래스 불균형 처리, Model Calibration, PhysioNet Utility Score 최적화를 경험한다. 또한 MSA(Microservice Architecture) 기반의 모델 서빙과 MLOps 파이프라인 구축을 통해 현업 수준의 AI 시스템 개발 역량을 확보한다.

이 미션은 팀 미션(3~5명)으로 수행한다. 각 팀은 명확한 역할을 지정하고(데이터 엔지니어, ML 엔지니어, 백엔드 개발자, 프론트엔드 개발자 등), README.md에 개인별 기여 내용을 문서화해야 한다. 기술 리포트에 '팀 역할 및 개인 작업 요약' 섹션을 포함해야 한다.

### 2. 최종 결과물

다음 내용이 포함된 깃허브(GitHub) 레포지토리 URL을 제출한다. 레포지토리는 아래의 구조를 갖춰야 한다.

1. **데이터 전처리 및 모델 학습 파이프라인**
    - 입력 : PhysioNet Challenge 2019 원시 데이터 (.psv 파일)
    - 출력 : 전처리된 특징 행렬 (.parquet), 학습된 모델 파일 (.pkl, .pt)
    - 기능 : 결측치 처리, SOFA 점수 계산, Sliding Window 특징 추출, XGBoost/LSTM 앙상블, Model Calibration, 5-Fold CV
2. **모델 서빙 API (FastAPI)**
    - 입력 : 환자 시계열 데이터 (JSON)
    - 출력 : 패혈증 위험도 점수, 위험 단계, SOFA 점수, SHAP 설명 (JSON)
    - 기능 : `/health`, `/predict`, `/predict_batch`, `/explain` 엔드포인트, Swagger UI 자동 생성
3. **임상 대시보드 (Streamlit)**
    - 입력 : API 서버 응답 데이터
    - 출력 : 실시간 모니터링 화면
    - 기능 : 환자 리스트 뷰(신호등 색상), 환자 상세 뷰(Vitals 추이, SOFA 막대 그래프), SHAP 시각화, Calibration Curve, 2단계 경보(Warning/Alert)
4. **기술 리포트 및 MLOps 환경**
    - Docker Compose 파일로 원클릭 실행 환경 (`docker-compose up`)
    - 모델 성능 평가 리포트 (AUROC, AUPRC, Utility Score, Calibration 분석)
    - README.md (아키텍처 다이어그램, 실행 방법, 성능 지표)
    - 실험 기록 (MLflow 또는 WandB 로그)
    - 기술 리포트는 다음 최소 목차를 포함해야 한다
        - 데이터 분리 및 누수 방지 증빙 (환자 ID 기반 분리 비율, 랜덤 시드)
        - AUROC/AUPRC/Utility Score + 임계값 분석
        - Calibration (Brier/ECE/보정 전후 비교)
        - Alert Fatigue 관점 (Precision-Recall Trade-off)
        - 선택한 임계값과 선택 근거 + 해당 임계값에서의 혼동행렬
        - 지연 측정 (환경 사양/요청 수/배치 크기)
        - 팀 역할 및 개인 작업 요약

### 3. 과제 목표

이 과제를 마친 후, 학습자는 아래를 스스로 설명할 수 있어야 한다.

- Sepsis-3 정의와 SOFA 점수 : Sepsis-3 진단 기준에서 SOFA 점수 6개 구성요소(호흡, 응고, 간, 심혈관, 신경, 신장)의 계산 방법과 Observation Window(24시간), Prediction Horizon(6시간)의 시계열 예측 구조를 설명할 수 있다.
- 클래스 불균형과 평가 지표 : 패혈증 양성 비율이 2~15%인 불균형 데이터에서 AUROC 대신 AUPRC를 중요하게 보는 이유와, PhysioNet Utility Score가 조기 예측에 보상하고 늦은 예측에 페널티를 부여하는 임상적 의미를 이해한다.
- Model Calibration : 예측 확률이 실제 발생 확률과 일치해야 하는 이유(임상적 의사결정 신뢰도)와 Brier Score, Platt Scaling의 원리를 설명할 수 있다.
- MSA 기반 모델 서빙 : 프론트엔드와 백엔드를 분리하여 API 통신으로 모델 추론을 수행하는 구조의 장점(확장성, 유지보수성)과 FastAPI 서빙 방식을 이해한다.
- 설명 가능 AI (XAI) : SHAP 값을 통해 모델의 예측 근거를 시각화하고, 의료진에게 판단 근거를 제공하는 방법을 설명할 수 있다.
- Alert Fatigue와 임상적 의사결정 : 오경보(False Alarm)가 의료진 피로를 유발하는 문제와 Precision-Recall 트레이드오프를 고려한 2단계 경보 전략을 이해한다.

### 4. 기능 요구 사항

다음 요구사항을 모두 만족해야 한다.

1. **데이터 전처리**
    - ~~PhysioNet Challenge 2019 데이터셋(training_setA, training_setB)을 로드해야 한다.~~
    - 원시 데이터(.psv)를 환자별로 병합하고 시간순으로 정렬해야 한다.
    - training_setA와 training_setB 병합 전 다음 필수 EDA 체크리스트를 수행해야 한다.
        - ~~setA와 setB 간 변수별 결측률 비교~~
        - ~~setA와 setB 간 측정 빈도 분포 비교~~
        - ~~setA와 setB 간 주요 변수 분포(HR, MAP, Lactate 등) 비교~~
        - ~~setA와 setB 간 패혈증 라벨 비율 비교~~
        - 유의미한 분포 차이 발견 시 대응 전략 문서화 (샘플 가중치, 도메인 적응 고려, 또는 근거 있는 직접 병합)
        - 결측치 처리는 Forward Fill, Linear Interpolation, KNN Imputation 중 하나 이상을 적용하고 선택 근거를 문서화해야 한다.
    - 활력징후 8종(HR, RR, Temp, SpO2, SBP, DBP, MAP, Resp)과 검사실 결과 10종(WBC, Lactate, Creatinine, Bilirubin, Platelet, INR, PaO2/FiO2, BUN, Glucose, pH)을 포함해야 한다.
    - SOFA 점수 6개 구성요소(호흡, 응고, 간, 심혈관, 신경, 신장)를 Sepsis-3 기준에 따라 계산해야 한다.
    - SOFA 점수 참조표
        
        
        | **SOFA 점수** | **0** | **1** | **2** | **3** | **4** |
        | --- | --- | --- | --- | --- | --- |
        | 호흡 (PaO2/FiO2) | ≥400 | <400 | <300 | <200 + 인공호흡 | <100 + 인공호흡 |
        | 응고 (혈소판, x10³/uL) | ≥150 | <150 | <100 | <50 | <20 |
        | 간 (빌리루빈, mg/dL) | <1.2 | 1.2-1.9 | 2.0-5.9 | 6.0-11.9 | ≥12.0 |
        | 심혈관 (MAP/승압제) | MAP≥70 | MAP<70 | Dopa≤5 또는 Dobu | Dopa>5 또는 Epi≤0.1 또는 NE≤0.1 | Dopa>15 또는 Epi>0.1 또는 NE>0.1 |
        | 신경계 (GCS) | 15 | 13-14 | 10-12 | 6-9 | <6 |
        | 신장 (크레아티닌, mg/dL) | <1.2 | 1.2-1.9 | 2.0-3.4 | 3.5-4.9 또는 <500 mL/day | ≥5.0 또는 <200 mL/day |
    - qSOFA 점수(호흡수 ≥22, 수축기혈압 ≤100, 의식 변화)를 계산해야 한다.
2. **특징 추출 (Feature Engineering)**
    - Observation Window는 24시간으로 설정해야 한다.
    - Prediction Horizon은 6시간으로 설정해야 한다 (패혈증 발생 6시간 전 예측).
    - Sliding Window 기반으로 각 변수의 통계적 특징(Mean, Std, Min, Max, Median, IQR, Skewness, Trend/Slope, Rate of Change, CV)을 추출해야 한다.
    - 추출된 특징 수는 최소 50개 이상이어야 한다.
    - Sepsis-3 기준 라벨링 : SOFA 점수가 baseline 대비 2점 이상 증가한 시점을 패혈증 발생으로 정의해야 한다.
    - 환자 ID(Subject ID) 기준으로 학습/검증/테스트를 분리하여 데이터 누수(Leakage)를 방지해야 한다.
3. **모델 학습**
    - Baseline 모델로 XGBoost 또는 LightGBM을 구현해야 한다.
    - Deep Learning 모델로 LSTM 또는 GRU를 구현해야 한다.
    - 앙상블 방식(Soft Voting 또는 Stacking)을 구현해야 한다.
    - 클래스 불균형 처리를 위해 Class Weight 또는 Focal Loss를 적용해야 한다 (시계열 특성상 SMOTE 사용 시 주의사항 문서화).
    - 5-Fold Cross Validation (환자 단위 Group K-Fold)을 적용해야 한다.
    - 하이퍼파라미터 튜닝 실험을 MLflow 또는 WandB로 기록해야 한다.
    - 최적 모델 파일(.pkl 또는 .pt)을 버전 관리해야 한다.
4. **Model Calibration**
    - Calibration Curve (Reliability Diagram)를 생성해야 한다.
    - Brier Score를 계산하고 0.15 이하를 목표로 해야 한다.
    - Expected Calibration Error (ECE)를 계산해야 한다.
    - Platt Scaling 또는 Isotonic Regression을 적용하여 보정 전후 성능을 비교해야 한다.
5. **성능 평가**
    - AUROC를 계산하고 0.82 이상을 달성해야 한다.
    - AUPRC (Average Precision)를 계산하고 0.40 이상을 달성해야 한다.
    - Sensitivity at 95% Specificity를 계산해야 한다.
    - Precision-Recall Curve를 생성해야 한다.
    - Confusion Matrix와 Classification Report를 생성해야 한다.
    - PhysioNet Utility Score를 구현하고 계산해야 한다 (공식 함수 참조).
    - 선택한 경보 임계값과 선택 근거(Utility/Recall/Alert Fatigue 관점)를 문서화해야 한다.
    - 선택한 임계값에서의 Confusion Matrix (또는 Recall/PPV/Specificity)를 제시해야 한다.
6. **모델 서빙 API (FastAPI)**
    - `/health` 엔드포인트 : 서버 상태 확인 (모델 로드 여부 반환).
    - `/predict` 엔드포인트 : 개별 환자 추론 (입력 유효성 검증 Pydantic 스키마 정의).
    - `/predict_batch` 엔드포인트 : 다수 환자 일괄 추론.
    - `/explain` 엔드포인트 : SHAP 또는 LIME 기반 판단 근거 반환.
    - 모델은 서버 시작 시점에 한 번만 메모리에 로드해야 한다 (Singleton 패턴).
    - 추론 시간은 환자 1명당 200ms 이내여야 한다.
    - 추론 시간 측정 조건
        - CPU 환경 (4코어 급, 예: Intel i5/Ryzen 5), 단일 환자 입력 (24시간 관찰 창), batch size=1, 10회 워밍업 후 100회 요청 평균. 평균과 P95 지연을 모두 보고한다.
    - Swagger UI(`/docs`)를 통한 API 명세서가 자동 생성되어야 한다.
7. **임상 대시보드 (Streamlit)**
    - 환자 리스트 뷰 : 전체 환자의 위험도를 신호등 색상(초록/노랑/빨강)으로 표시해야 한다.
    - 환자 상세 뷰 : 선택된 환자의 Vital Sign 시계열 그래프와 위험도 변화 추이를 시각화해야 한다.
    - SOFA 점수 구성요소별 막대 그래프를 표시해야 한다.
    - SHAP Force Plot 또는 Waterfall Plot을 표시해야 한다.
    - Calibration Curve를 표시해야 한다.
    - 2단계 경보 시스템 : Warning (0.5~0.75)과 Alert (0.75 이상)로 구분하여 시각적 경고를 표시해야 한다.
    - API 서버와 통신하여 데이터를 갱신해야 한다 (프론트엔드에서 모델 직접 로드 금지).
8. **MLOps 환경**
    - Docker Compose 파일로 API 서버와 대시보드를 원클릭 실행해야 한다.
    - `requirements.txt` 또는 `Dockerfile`에 라이브러리 버전을 명시해야 한다.
    - 환경 변수(.env)로 민감 정보(API Key, DB 접속 정보 등)를 관리해야 한다.
    - README.md에 실행 방법, 아키텍처 다이어그램, 성능 지표를 명시해야 한다.
9. **문서화**
    - 데이터 전처리 과정과 결측치 처리 전략을 문서화해야 한다.
    - 모델 학습 과정과 하이퍼파라미터 선택 근거를 문서화해야 한다.
    - 성능 평가 결과 (AUROC, AUPRC, Utility Score, Calibration)를 리포트로 작성해야 한다.
    - Utility Score가 AUROC와 다른 이유를 분석하여 문서화해야 한다.

### 5. 보너스 과제 (선택)

1. CI/CD 파이프라인 및 부하 테스트
    - 해야 할 작업 : GitHub Actions를 사용하여 코드 푸시 시 자동으로 유닛 테스트와 린트 검사를 수행하고, Locust를 활용하여 동시 접속자 50명 이상일 때 API 서버의 응답 속도를 측정한다.
    - 배움 포인트 : 현업에서 필수적인 CI/CD 환경과 성능 프로파일링 기법을 경험하고, 대규모 트래픽 상황에서 시스템 안정성을 확보하는 방법을 이해한다.
2. 패혈증 하위 표현형(Subphenotype) 분류
    - 해야 할 작업 : K-Means 또는 GMM 클러스터링을 활용하여 패혈증 환자를 3~4개 그룹(α, β, γ, δ형)으로 분류하고, 각 그룹의 생리학적 특성과 예후(사망률) 차이를 분석한다.
    - 배움 포인트 : 패혈증의 이질성(Heterogeneity)과 Precision Medicine 접근 방식을 이해하고, 비지도 학습의 임상적 활용을 경험한다.
3. 데이터 드리프트 모니터링 및 모델 경량화
    - 해야 할 작업 : 학습 데이터와 실시간 데이터의 분포 차이를 PSI(Population Stability Index)로 측정하고, 예측 모델을 ONNX로 변환하여 추론 속도를 50% 이상 단축한다.
    - 배움 포인트 : 배포 후 모델 성능 저하를 조기에 감지하는 MLOps 모니터링과 엣지 디바이스 배포를 위한 모델 최적화 기법을 경험한다.

    이 미션의 핵심인 PhysioNet Challenge 2019 데이터셋은 공개되어 있으나, 연구 목적의 데이터이므로 절차에 따른 접근이 필요합니다.
    
    메인 데이터셋: PhysioNet Computing in Cardiology Challenge 2019
    
    데이터 내용 :
    
    - ICU 환자 40,336명의 시간별(Hourly) 생체 신호(HR, Temp, SBP 등), 검사 결과(Lab), 인구통계 정보
    - 타겟 라벨(`SepsisLabel`): 패혈증 발병 6시간 전부터 1로 표기됨 (Shifted Label)
    
    획득 방법 :
    
    1. 회원 가입: PhysioNet 웹사이트에 접속하여 계정을 생성한다.
    2. 프로젝트 검색: 상단 검색창에 "PhysioNet Computing in Cardiology Challenge 2019"를 검색한다.
    3. 라이선스 동의: 페이지 하단의 'Files' 섹션 접근 시 Data Use Agreement 팝업이 뜬다. "I agree"를 클릭하면 즉시 다운로드 권한이 부여된다 (별도의 승인 대기 시간 없음).
    4. 다운로드: `training_setA.zip`, `training_setB.zip`을 다운로드한다.
        - 폴더 구조 권장:
            
            ```
            data/
            ├── raw/
            │   ├── training_setA/ (p000001.psv, ...)
            │   └── training_setB/
            └── processed/ (전처리 완료된 .parquet 파일들)
            ```
            
    5. 보조 데이터셋 (선택): MIMIC-IV Demo
        - 목적 : 실제 병원 EMR 데이터베이스(PostgreSQL) 구조를 경험해보고 싶을 때 활용.
        - 내용 : 100명의 환자에 대한 상세 임상 기록.
        - 획득 : PhysioNet의 `MIMIC-IV Demo` 프로젝트 페이지에서 위와 동일한 방식으로 다운로드 가능.
