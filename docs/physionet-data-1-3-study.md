# PhysioNet 2019 실제 데이터로 공부하는 Data Specification 1·2·3

> 대상: 패혈증·의학·의료 데이터가 처음인 팀원  
> 조사일: 2026-09-16  
> 조사 대상: `physionet-data/physionet.org/files/challenge-2019/1.0.0/training/training_setA`, `training_setB`

이 문서는 빈 양식의 다음 세 부분을 **실제 내려받은 파일**을 기준으로 정리한다.

1. 데이터 목적과 관측 단위
2. 데이터 출처와 수집 계획
3. Feature·Target 스키마

의학 용어는 처음 나오는 자리에서 `쉬운 설명`을 붙였다. 실제 측정값의 임상적 해석은 의료진의 진단을 대신하지 않는다.

## 먼저 알아야 할 핵심 용어

| 용어 | 쉬운 설명 |
| --- | --- |
| **패혈증(Sepsis)** | 감염에 대한 몸의 반응이 지나쳐 장기가 손상되는 위급한 상태. 단순히 “균이 피에 있는 병”만 뜻하지 않는다. |
| **ICU (Intensive Care Unit)** | 중환자실. 상태가 위중해 지속적인 관찰과 치료가 필요한 환자가 머무는 곳. |
| **활력징후(Vital signs)** | 심박수·혈압·호흡수·체온·산소포화도처럼 현재 몸 상태를 빠르게 보여주는 기본 측정값. |
| **검사값(Laboratory values)** | 혈액 등을 채취해 검사실에서 측정한 수치. 활력징후보다 측정 횟수가 적은 경우가 많다. |
| **Sepsis-3** | 현재 널리 쓰이는 패혈증 정의 체계. 감염이 의심되는 상황에서 장기 기능이 급격히 나빠졌는지를 본다. |
| **SOFA 점수** | 호흡·응고·간·심혈관·신경·신장, 여섯 장기계의 기능 저하를 점수화한 것. 높을수록 장기 기능이 나쁘다는 뜻이다. |
| **Feature(특징)** | 모델이 예측할 때 입력으로 보는 정보. 예: 현재 심박수, 24시간 평균 체온. |
| **Target(타깃, 정답)** | 모델이 맞혀야 하는 정답. 여기서는 `SepsisLabel` 0 또는 1. |
| **시계열(Time series)** | 시간 순서대로 기록된 데이터. 이 데이터는 환자별로 1시간 간격의 행을 가진다. |
| **결측값(Missing value, NaN)** | 측정되지 않아 값이 없는 상태. 0이 아니다. `NaN`은 “Not a Number” 표기다. |
| **관측 창(Observation window)** | 한 번 예측할 때 뒤돌아보는 과거 구간. 우리 프로젝트는 최근 24시간으로 정했다. |
| **예측 지평(Prediction horizon)** | 얼마나 앞의 일을 예측할 것인지 나타내는 미래 구간. 이 과제의 핵심은 6시간 선행 예측이다. |
| **데이터 누수(Data leakage)** | 실제 예측 시점에는 알 수 없는 미래 정보나 정답이 Feature에 섞이는 문제. 점수는 높아 보여도 현실에서는 작동하지 않는다. |

# 1. 데이터 목적과 관측 단위

## 1.1 AI Task

**선택: `Classification`(분류)**

이 모델의 최종 정답은 `SepsisLabel = 0 또는 1`이다.

- `0`: 해당 시간의 공식 라벨이 패혈증 경보 구간이 아님
- `1`: 공식 패혈증 발생 시각보다 6시간 앞선 시각에 도달했거나 그 이후임

시계열을 사용하지만 다음 시간의 심박수 같은 연속값을 맞히는 문제가 아니므로 드롭다운의 `Forecasting`이 아니라 `Classification`이 알맞다.

## 1.2 데이터 목적

> ICU 환자의 시각 `t`까지 얻은 임상 데이터를 사용해, 패혈증을 임상적으로 확인하는 시점보다 최대 6시간 일찍 위험을 분류하고 위험 확률을 제공한다.

우리 프로젝트에서는 원본 데이터 위에 다음 규칙을 추가한다.

- **관측 창:** 시각 `t`까지 최근 24시간
- **갱신 주기:** 1시간마다 한 번
- **출력:** 패혈증 위험 확률 + 이진 분류 + 경보 단계
- **사용자:** ICU 의료진. 예측은 진단을 대신하지 않고 확인이 필요한 환자를 먼저 살피도록 돕는다.

### 중요한 구분: 데이터의 공식 라벨과 우리 문장

“앞으로 6시간 이내 패혈증 발생”이라고 간단히 말할 수 있지만, 실제 `SepsisLabel`은 더 정확히 다음과 같다.

```text
패혈증 발생 시각 = t_sepsis
현재 행의 시간 = t

if t >= t_sepsis - 6:
    SepsisLabel = 1
else:
    SepsisLabel = 0
```

따라서 라벨은 발생 6시간 전부터 1이 되고, **발생 후에도 계속 1**이다. 즉 양성 행 전부가 “앞으로 6시간 안에 새로 발생”을 뜻하지는 않는다. 이 차이는 모델 학습 범위를 정할 때 반드시 문서화해야 한다.

## 1.3 관측 단위

| 단계 | 실제 의미 | 예시 |
| --- | --- | --- |
| 파일 1개 | ICU 환자 기록 1건 | `p005863.psv` |
| 행 1개 | 해당 환자의 특정 ICU 시간 1개 | `ICULOS=10` |
| 열 1개 | 그 시간의 측정값 또는 환자 정보 | `HR=80`, `Temp=37.3` |
| 학습 샘플 1개 | 환자 1명 × 예측 기준 시각 `t` | `t`까지 최근 24시간 → `SepsisLabel[t]` |

기본 키는 `patient_id + ICULOS`다.

- `patient_id`: 파일명에서 얻는 환자 기록 식별자
- `ICULOS`: ICU Length of Stay, ICU 입실 후 경과 시간

### 실제 파일에서 확인한 시간 구조

| 검사 항목 | setA | setB | 해석 |
| --- | ---: | ---: | --- |
| 파일 수 | 20,336 | 20,000 | 파일 1개가 환자 기록 1건 |
| 전체 행 수 | 790,215 | 761,995 | 합계 1,552,210시간 행 |
| 환자당 행 수 최소 | 8 | 8 | 최소 8시간 기록 |
| 중앙값 | 39시간 | 38시간 | 환자의 절반은 이보다 짧고 절반은 김 |
| 평균 | 38.858시간 | 38.100시간 | 환자당 약 38시간 |
| 95백분위 | 58시간 | 58시간 | 환자의 95%가 약 58시간 이하 |
| 최대 | 336시간 | 336시간 | 14일. 원 대회가 이 길이로 잘랐음 |
| 중복 시간 행 | 0 | 0 | 같은 환자에서 동일 ICULOS 중복 없음 |
| 빠진 시간 칸 | 0 | 0 | 각 파일 안에서 ICULOS가 1씩 연속 |
| 역순 환자 | 0 | 0 | 시간 순서 정상 |

**중앙값**은 크기순으로 세웠을 때 가운데 값이다. 일부 매우 긴 입원 기록의 영향을 평균보다 덜 받는다.  
**95백분위**는 환자의 95%가 그 값 이하라는 뜻이다.

### 24시간 창에서 생기는 문제

최소 기록은 8시간인데 우리 관측 창은 24시간이다. 따라서 ICU 입실 초기에는 24시간이 다 차지 않는다.

권장 규칙:

1. `t < 24`여도 예측 샘플로 사용할 수 있다.
2. 실제로 존재하는 입실 이후 데이터만 사용한다.
3. 부족한 과거는 `NaN`과 결측 표시로 남긴다.
4. 미래 행을 가져와 채우지 않는다. 이것은 데이터 누수다.

## 1.4 Target의 실제 분포

| 항목 | setA | setB | 합계 |
| --- | ---: | ---: | ---: |
| 환자 기록 | 20,336 | 20,000 | 40,336 |
| 패혈증 환자 | 1,790 | 1,142 | 2,932 |
| 환자 단위 양성률 | 8.8021% | 5.7100% | 7.2690% |
| 시간 행 | 790,215 | 761,995 | 1,552,210 |
| 양성 시간 행 | 17,136 | 10,780 | 27,916 |
| 시간 행 양성률 | 2.1685% | 1.4147% | 1.7985% |
| 첫 양성 `ICULOS` 중앙값 | 29.5h | 28.5h | — |

`환자 단위 양성률`과 `행 단위 양성률`은 다르다.

- 환자 단위: 그 환자에게 양성 행이 한 번이라도 있는가?
- 행 단위: 전체 시간 행 중 라벨 1인 행이 몇 개인가?

양성 행이 약 1.8%뿐이라 **클래스 불균형**이 심하다. 클래스 불균형은 정답 0이 1보다 압도적으로 많은 상태다. 모델이 전부 0으로 말해도 Accuracy(정확도)는 높아 보일 수 있으므로 Accuracy만 평가하면 안 된다.

권장 지표:

- **AUPRC:** 희소한 양성 패혈증을 얼마나 정확히 찾는지 보기 좋은 지표
- **AUROC:** 양성과 음성을 전반적으로 구분하는 능력
- **Brier score:** 예측 확률이 실제 결과와 얼마나 맞는지 측정. 낮을수록 좋음
- **Utility score:** 너무 늦거나 지나치게 이른 경보, 거짓 경보를 임상적 비용으로 평가하는 공식 지표

## 1.5 1번 양식에 넣을 최종 문장

**데이터 목적**  
ICU 시각 `t`까지 수집된 활력징후·검사값·인구통계와 최근 24시간 변화량으로 PhysioNet 공식 `SepsisLabel`을 이진 분류하고, 임상 패혈증 발생 시점보다 최대 6시간 빠른 위험 확률을 제공한다.

**관측 단위**  
원본 한 파일은 ICU 환자 기록 1건, 한 행은 환자 × ICU 경과 1시간이다. 학습 샘플은 `(patient_id, ICULOS=t)`를 기준으로 최대 24시간의 과거 관측과 시각 `t`의 `SepsisLabel`을 묶는다.

**Target 정의**  
`SepsisLabel`은 int형 0/1이다. 패혈증 환자에서는 `t ≥ t_sepsis−6`부터 1이고 이후에도 1이 유지되며, 비패혈증 환자는 전 시간 0이다. 원본 공식 라벨을 사용하고 임의로 재생성하지 않는다.

**예측 시점과 Horizon**  
ICU 입실 후 매시간 `t`에 최근 최대 24시간만 사용해 공식 발생 시점 6시간 전부터 패혈증 위험을 탐지한다. `t` 이후 측정값은 사용하지 않는다.

# 2. 데이터 출처와 수집 계획

## 2.1 데이터는 어디서 왔는가?

데이터셋: **PhysioNet/Computing in Cardiology Challenge 2019**  
주제: 임상 데이터로 패혈증을 조기에 예측하기  
버전: 1.0.0  
DOI: `10.13026/v64v-d857`

**PhysioNet**은 생리신호와 임상 연구 데이터를 제공하는 연구 플랫폼이다.  
**Computing in Cardiology Challenge**는 같은 데이터와 평가기준으로 여러 팀의 알고리즘을 비교하는 국제 대회다.

공식 설명상 공개 학습 데이터는 서로 다른 두 병원 시스템의 ICU 기록이다.

- setA: Beth Israel Deaconess Medical Center 계열
- setB: Emory University Hospital 계열
- 병원 C: 대회 숨김 평가용. 현재 내려받은 공개 training 폴더에는 없음

## 2.2 실제 확보 상태

| 영역 | 로컬 경로 | 파일 | 행 | 확보 상태 |
| --- | --- | ---: | ---: | --- |
| setA | `.../training/training_setA` | 20,336 | 790,215 | 확보·검사 완료 |
| setB | `.../training/training_setB` | 20,000 | 761,995 | 확보·검사 완료 |
| 합계 | `.../training` | 40,336 | 1,552,210 | 확보·검사 완료 |
| 병원 C | 없음 | — | — | 미공개·사용 불가 |

실제 모든 40,336개 파일에서 다음을 확인했다.

- 컬럼 수 41개로 동일: 입력 후보 40개 + Target 1개
- 스키마가 다른 파일 0개
- 중복 `ICULOS` 0개
- 시간 간격 누락 0개
- 시간이 역순인 환자 0명
- `SepsisLabel`이 1에서 다시 0으로 내려가는 환자 0명

## 2.3 원본 데이터는 어떻게 만들어졌는가?

각 파일은 파이프(`|`)로 열을 구분한 `.psv` 텍스트다. CSV에서 쉼표 대신 `|`를 쓴 형태다.

```text
HR|O2Sat|Temp|...|ICULOS|SepsisLabel
80|100|36.78|...|6|0
80|100|NaN|...|7|0
```

한 시간에 여러 번 측정된 값이 있으면 원 대회 데이터 제작 과정에서 시간 단위로 요약됐다. 따라서 우리 팀이 가진 파일은 원시 모니터 신호가 아니라 **이미 1시간 단위로 가공된 임상 표**다.

| 데이터 영역 | 출처·소유자 | 수집 항목 | 기간·주기 | 실제 확보 상태 | 권한·주의사항 |

**EMR(Electronic Medical Record)**은 전자의무기록이다. 진료·검사·투약 등을 전산으로 저장하는 병원 시스템을 뜻한다.

## 2.5 개인정보·권한에서 알아둘 것

- 데이터는 비식별화되어 이름·주민번호 같은 직접 식별자가 없다.
- 파일명 `patient_id`도 실제 병원 환자번호로 취급하지 않는다.
- 비식별 데이터라도 건강정보이므로 재식별을 시도하면 안 된다.
- 원본 `.psv`, 처리 `.parquet`, 환자별 예측 결과는 GitHub에 올리지 않는다.
- 코드·스키마·집계 통계만 저장소에서 공유한다.
- 데이터 이용조건과 인용 요구사항을 최종 제출 전에 다시 확인한다.

## 2.6 setA와 setB를 같은 데이터로 보면 안 되는 이유

두 세트는 측정 관행이 상당히 다르다.

예시:

| 변수 | setA 결측률 | setB 결측률 | 차이 해석 |
| --- | ---: | ---: | --- |
| `DBP` | 48.126% | 13.945% | 이완기 혈압 기록 관행이 크게 다름 |
| `Resp` | 9.777% | 21.139% | setB에서 호흡수 누락이 더 많음 |
| `EtCO2` | **100.000%** | 92.436% | setA에는 값이 하나도 없음 |

### 검사값 결측을 읽는 법

예를 들어 setA의 `Lactate` 결측률 96.565%는 “환자의 96.565%가 젖산 검사를 한 번도 안 했다”는 뜻이 아니다. **전체 시간 행 중 96.565%에서 해당 시간의 값이 비어 있다**는 뜻이다. 하루에 한 번 검사했다면 나머지 시간 행은 대부분 NaN이 된다.

따라서 다음을 함께 만들어야 한다.

- 마지막으로 관측한 값 (`last`)
- 마지막 검사 후 몇 시간이 지났는지 (`hours_since`)
- 최근 24시간 동안 몇 번 측정됐는지 (`count`)
- 그 시간에 측정됐는지 (`measured`)
- 최근 24시간 결측 비율 (`missing_rate`)

## 3.7 SOFA·qSOFA를 Feature로 쓸 때의 한계

**qSOFA**는 병상에서 빠르게 위험을 확인하는 간단한 점수다. 보통 낮은 수축기 혈압, 빠른 호흡, 의식 변화 세 항목을 본다.

하지만 이 데이터에는 다음이 없다.

- GCS: 의식 수준 점수
- 승압제: 혈압을 올리는 약
- 소변량
- PaO2: 동맥혈 산소분압
- 배양·항생제 시각

따라서 완전한 SOFA·qSOFA를 정확히 재현할 수 없다.

| 점수 영역 | 사용할 수 있는 값 | 한계 |
| --- | --- | --- |
| 호흡 | `O2Sat`, `FiO2` | 정식 SOFA의 PaO2/FiO2 비율 계산 불가 |
| 응고 | `Platelets` | 계산 가능 |
| 간 | `Bilirubin_total` | 계산 가능하지만 결측 매우 큼 |
| 심혈관 | `MAP` | 승압제 정보가 없어 고점수 계산 불가 |
| 신경 | 없음 | GCS 없어 계산 불가 |
| 신장 | `Creatinine` | 소변량 항목 없음 |
| qSOFA | `SBP`, `Resp` | 의식 항목 없음. 3점 만점이 아닌 2개 항목만 |

그래서 원본 `SepsisLabel`을 SOFA 계산값으로 덮어쓰지 않는다. 부분 SOFA는 별도 이름(예: `partial_sofa`)으로 Feature·설명용으로만 사용한다.

## 3.8 다른 Challenge 팀들은 SOFA를 어떻게 다뤘는가?

결론부터 말하면, **다른 팀들도 공개된 40개 변수만으로 표준 SOFA 6요소를 완전하게 계산하지 못했다.** 일부 팀은 SOFA를 아예 쓰지 않고 원본 변수와 시간 변화량으로 학습했고, 일부 팀은 계산 가능한 항목만 묶어 `PartialSOFA`, `pseudo-SOFA`, `SOFA-related features`라는 이름으로 사용했다.

### 사례 1: PartialSOFA와 24시간 악화 여부

CinC 2019 논문 014 팀은 Challenge 데이터와 SOFA 양쪽에 공통으로 들어 있는 변수만 사용해 **PartialSOFA(부분 SOFA)**를 만들었다.

- `PartialSOFA`: 계산 가능한 SOFA 관련 점수의 합
- `SOFA_Deterioration`: 이전 24시간과 비교해 PartialSOFA가 2점 이상 증가했는지 나타내는 0/1 Feature
- 함께 사용한 Feature: Shock Index, BUN/Creatinine 비율, 측정 횟수, 구간별 최솟값·최댓값
- 결측값은 환자 안에서 과거 값으로 Forward-fill한 뒤 Feature를 계산

**Shock Index**는 `HR / SBP`, 즉 심박수를 수축기 혈압으로 나눈 값이다. 순환 상태가 불안정한지 참고하는 간단한 지표다.

### 사례 2: 네 항목만 사용한 SOFA-related score

CinC 2019 논문 192 팀은 공개 데이터에서 직접 계산 가능한 다음 네 항목을 점수로 변환했다.

| 항목 | 공개 변수 | 계산 가능 범위 |
| --- | --- | --- |
| 응고 | `Platelets` | 0~4점 |
| 간 | `Bilirubin_total` | 0~4점 |
| 신장 | `Creatinine` | Creatinine 기준 0~4점. 소변량 기준은 없음 |
| 심혈관 | `MAP` | MAP&lt;70이면 1점. 승압제 정보가 없어 2~4점 불가 |

그리고 네 점수를 합친 값을 Feature로 사용했다. 이것은 표준 6요소 SOFA가 아니라 **4개 항목의 부분 합계**다.

### 사례 3: pseudo-SOFA

CinC 2019 논문 269 팀은 필요한 변수가 빠져 있다는 점을 명시하고 계산 결과를 **pseudo-SOFA(유사 SOFA)**라고 불렀다.

`pseudo`는 “진짜와 완전히 같지는 않지만 비슷하게 만든 것”이라는 뜻이다. 이 팀은 qSOFA와 관련된 다음 이진 Feature도 사용했다.

- `Resp ≥ 22`: 호흡수가 분당 22회 이상인가?
- `SBP ≤ 100`: 수축기 혈압이 100 mmHg 이하인가?

하지만 의식 상태가 없으므로 완전한 qSOFA 3개 항목은 아니다.

### 사례 4: SOFA라고 기록했지만 처리 방법이 불분명한 경우

일부 Challenge 초록은 매시간 SOFA·qSOFA·NEWS를 계산했다고 보고했다. 그러나 공개 데이터에 없는 GCS·승압제·소변량·PaO2를 어떻게 처리했는지 자세한 설명이 없어, 그 결과를 표준 SOFA와 같다고 확인할 수 없다.

**NEWS(National Early Warning Score)**는 호흡수·산소포화도·체온·혈압·맥박·의식 수준 등으로 환자 악화 위험을 보는 조기경보 점수다. 이 데이터에는 의식 수준이 없어 NEWS도 완전한 형태로는 계산하기 어렵다.

### 우리 프로젝트에서 선택할 수 있는 방법

#### 선택 A — SOFA 계열 Feature를 사용하지 않음

원본 변수의 현재값·추세·변동·결측 패턴을 모델이 직접 학습한다.

```text
HR, MAP, Resp, O2Sat, Creatinine, Platelets 등
                ↓
last / mean / min / max / slope / missingness
                ↓
패혈증 위험 확률
```

장점:

- 불완전한 점수를 임상 점수로 오해할 위험이 없음
- 원본 데이터가 제공하는 범위에 충실함
- 어떤 변수가 예측에 영향을 줬는지 SHAP으로 설명 가능

#### 선택 B — 4개 항목 PartialSOFA를 보조 Feature로 사용

```text
PartialSOFA =
    platelet_score
  + bilirubin_score
  + creatinine_score
  + map_score
```

추가로 현재 점수가 이전 24시간 최저값보다 2점 이상 증가했는지를 만들 수 있다.

```text
partial_sofa_delta_24h =
    현재 PartialSOFA - 이전 24시간 PartialSOFA 최저값

partial_sofa_deterioration_24h =
    1 if partial_sofa_delta_24h >= 2 else 0
```

주의:

1. 이름을 `SOFA`가 아니라 반드시 `PartialSOFA` 또는 `4-component SOFA-related score`로 쓴다.
2. 빠진 항목을 0점으로 처리하면 “정상”과 “측정 불가”가 섞이므로 구성 항목이 하나도 없으면 합계도 결측으로 둔다.
3. Forward-fill은 같은 환자의 **과거 값만** 사용한다. 미래 값을 가져오면 데이터 누수다.
4. `PartialSOFA +2`는 공식 Sepsis-3의 `SOFA +2`와 같은 뜻이 아니다.
5. 원본 `SepsisLabel`을 다시 생성하거나 수정하는 데 사용하지 않는다.

### 현재 권장 결론

첫 Baseline에서는 **선택 A**, 즉 SOFA 없이 원본 변수와 시간 변화 Feature로 학습한다. 그다음 별도 실험에서 선택 B의 PartialSOFA를 추가하고 AUPRC·Utility·Brier가 실제로 좋아지는지 비교한다.

PartialSOFA가 도움이 되지 않으면 제거한다. 도움이 되더라도 대시보드에는 “표준 SOFA”가 아니라 “공개 데이터 4개 항목 기반 부분 점수”라고 표시한다.

# 실제 데이터 조사 방법과 재현

집계 결과 원본: `docs/physionet-actual-profile.json`

# 이번 조사에서 기존 초안보다 달라진 사실

1. 공개 데이터의 실제 합계는 **40,336파일, 1,552,210행**이다.
2. 실제 양성은 환자 2,932명(7.2690%), 시간 행 27,916개(1.7985%)다.
3. setA의 `EtCO2`는 **100% 결측**이라 기본 Feature 채택을 재검토해야 한다.
4. setA/B의 결측 패턴 차이가 매우 커 병원 일반화 평가가 필요하다.
5. setB의 실제 최소 나이는 **14세**이므로 “성인만”이라고 단정하지 않는다.
6. 공개 파일에는 PaO2·GCS·승압제·소변량·배양·항생제가 없어 완전한 SOFA와 Sepsis-3 라벨을 재생성할 수 없다.
7. `SepsisLabel=1`은 발생 6시간 전부터 시작해 발생 후에도 유지된다. 단순한 “앞으로 6시간 이내”와 완전히 같지 않다.
