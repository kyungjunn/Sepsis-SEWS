# SEWS 특징 추출 및 AI 모델링 최신 설계

작성일: 2026-10-05
상태: 구현 전 설계. 성능 수치는 목표이며 달성 결과가 아니다.

## 1. 분석 결론과 AI 목표

**최근 최대 24시간의 ICU 기록으로 매시간 공식 `SepsisLabel`의 양성 위험 점수를 예측한다.** XGBoost → LSTM 비교 → Soft Voting → Calibration → 경보 임계값 선택이라는 방향은 적절하다. 다만 앙상블의 개선은 보장되지 않으며 단일 모델과 비교해야 한다.

공식 라벨은 발생 약 6시간 전부터 양성이고 발생 후에도 유지된다. 따라서 출력은 엄밀한 ‘향후 6시간 내 신규 발생 확률’이 아니라 **공식 양성 라벨에 대한 보정 확률**이다. 조기 발견 여부는 별도 시간 기반 평가로 확인한다. 이미 선행 처리된 라벨을 다시 6시간 이동하지 않는다.

### 사용자 초안에서 수정한 사항

- Max는 가장 **높은** 값이다.
- pH는 혈액의 **산성·알칼리성** 지표이지 혈액 산소 수치가 아니다.
- FiO2는 검사 결과라기보다 산소 공급 정보를 나타내며 PaO2/FiO2와 다른 변수다.
- SOFA 2점 상승만으로 Sepsis-3가 성립하지 않는다. 감염 의심 조건도 필요하다.
- X와 y를 먼저 만드는 것은 환자별 순수 계산에 한해 가능하지만, 대치·스케일링 등 데이터에서 기준을 학습하는 처리는 반드시 분할 후 수행한다.
- 인구통계, Lactate 최근값, HR 변화량은 아래 160개 통계 특징에 자동 포함되지 않는다. 추가 실험으로 구분한다.

정답 컬럼은 정확히 `SepsisLabel`이다. 입력에 포함하지 않는다. `patient_id`는 파일명에서, `hospital_set`은 A/B 폴더에서 생성한다. `ICULOS`는 시간축과 창 구성에 사용한다. 이 세 메타데이터는 기본 160개 모델 특징이 아니다. 파일명이 병원 간 중복될 가능성에 대비해 기록 키는 `(hospital_set, patient_id, ICULOS)`로 관리한다.

Age·Gender·HospAdmTime은 기본안에서 제외하고 인구통계 확장 실험에서 별도로 비교한다. 현재 입력을 ‘인구통계 포함’이라고 기술하지 않는다.

## 3. 24시간 창과 전처리

시각 t의 창은 `[max(입실 시각, t−23), t]`이며 미래 시점은 사용하지 않는다. 최초 24시간 미만도 예측 대상이다.

1. 환자별 시간 정렬, 헤더·라벨·시간 중복·역순·간격 검증.
2. 임상 범위와 단위 검증. 이상값을 처리하더라도 행을 임의 삭제하지 않고 사유를 기록한다. FiO2 단위를 확인하고 분율로 통일한다.
3. 기본 통계는 **창 내 실제 관측값**으로 계산한다. 결측을 0이나 정상값으로 간주하지 않는다. 희소 검사값의 변동성을 임의 보간으로 만들지 않는다.
4. LSTM 값 채널은 환자 내 과거 관측값만 forward fill한다. 초기 미측정 값은 학습 세트의 변수별 중앙값으로 대치한다. fold마다 중앙값을 다시 학습한다.
5. LSTM 스케일러도 해당 학습 환자만으로 fit한다. XGBoost는 기본적으로 NaN 처리를 활용하며 불필요한 표준화를 하지 않는다.
6. 미래값을 사용하는 backfill·양방향 선형 보간·전체 입원 평균 대치를 금지한다.

측정 여부와 마지막 측정 후 시간은 관측 원본에서 계산한다. ffill한 값을 새 측정으로 세지 않는다. 관측 전 경과 시간은 명시적 미측정 플래그로 구분하고, 경과 시간의 상한·인코딩은 설정에 기록한다.

## 4. 특징 추출: 16개 × 10개 = 160개

기본 XGBoost 입력은 **환자×예측 시각마다 숫자 160개**다. 특징명은 `{원본컬럼}_{통계명}`으로 고정한다. 예: `HR_mean`, `MAP_min`, `Lactate_slope`.

창 내 관측값을 시간순 `(τ_i, x_i)`, 개수를 n이라 한다. 시간 단위는 시간이다.

| 특징 | 계산 정의 | 최소 관측 수·주의 |
| --- | --- | --- |
| Mean | 관측값 산술평균 μ | n≥1 |
| Std | 표본 표준편차 s, ddof=1 | n≥2 |
| Min | 관측 최솟값 | n≥1 |
| Max | 관측 최댓값 | n≥1 |
| Median | 50% 분위수 | n≥1 |
| IQR | Q75−Q25, 선형 분위수 보간 | n≥2 |
| Skewness | 편향 보정 Fisher–Pearson 왜도 | n≥3, 분산>0 |
| Trend/Slope | 실제 τ에 대한 최소제곱 직선 기울기 | n≥2, 서로 다른 시각 |
| Rate of Change | 인접 관측 쌍의 `abs(x_i−x_(i−1))/(τ_i−τ_(i−1))` 평균 | n≥2 |
| CV | s/abs(μ), 비율로 저장 | n≥2, abs(μ)>1e−8 |

- 계산 조건을 만족하지 않으면 NaN이다. 상수 시계열은 Std·IQR·Slope·Rate of Change가 0이고 왜도는 정의 불가로 NaN이다.
- Skewness가 양수면 큰 값 방향으로 긴 꼬리, 음수면 작은 값 방향으로 긴 꼬리다. 단순히 ‘값이 위쪽에 몰렸다’와 같지 않다.
- Rate of Change는 **단기 변화의 크기**로 정의했다. 방향은 Slope로 표현한다. 부호 있는 평균 차이는 상승·하락이 상쇄되고 순변화와 겹치므로 기본안에 사용하지 않는다.
- 검사값이 매시간 존재하지 않으므로 실제 시간 간격으로 나눈다. 한 번만 측정된 값으로 변화율을 만들지 않는다.
- CV는 온도처럼 원점이 임의적인 척도에서 임상적 상대 변동성 해석에 한계가 있다. 과제 요구로 생성하되 해석·제거 실험을 별도 기록한다.

### 권장 추가 특징: 기본 160개와 구분

각 변수의 최근값, 창 내 관측 수, 결측률, 마지막 측정 후 시간을 추가 비교한다. 4개씩 추가하면 64개가 추가되어 224개다. 전부 미측정이면 최근값은 NaN이다. 특히 희소 검사에서는 측정 패턴 자체가 중요한 후보지만 병원 관행을 학습할 위험이 있으므로 A/B별 성능을 확인한다.

## 5. y와 Sepsis-3/SOFA 요구사항

**학습 y는 원본 `SepsisLabel[t]`를 사용한다. SOFA로 덮어쓰지 않는다.** 첫 양성 이후에도 1이 유지되는 공식 과제를 따른다. 라벨 또는 라벨에서 계산한 발생 시각·환자 양성 여부는 모델 입력으로 금지한다. 환자 양성 여부는 분할 층화와 평가에만 사용한다.

Sepsis-3는 감염 의심과 급성 SOFA 상승을 함께 다룬다. 공개 데이터에는 완전한 SOFA와 감염 의심 시각을 재구성하는 데 필요한 PaO2·GCS·승압제 용량·소변량·항생제 및 배양 시각 등이 없다. 따라서 다음을 구분한다.

- 공식 라벨: 대회가 제공한 정답. 기본 학습 및 Utility 평가에 사용.
- 부분 SOFA: 관측 가능한 혈소판·빌리루빈·크레아티닌 등으로 계산한 부분 구성요소. 완전한 SOFA나 패혈증 확진으로 표시하지 않는다.
- 부분 qSOFA: Resp·SBP만으로 의식 변화 항목까지 채웠다고 주장하지 않는다.

원본 미션의 완전한 SOFA·qSOFA 및 직접 Sepsis-3 라벨링 요구와 충돌하므로, 데이터 한계를 제출 문서에 명시하고 대체 인정 범위는 과제 담당자에게 확인해야 한다. 없는 항목을 0점으로 채워 충족했다고 주장하지 않는다.

## 6. 환자 분할과 누수 방지

추천 기본 실험은 **A/B 각각 환자 단위 70/15/15 분할 후 같은 용도끼리 병합**, seed=42다. A/B별 환자 양성 여부로 층화하고 정확한 인원과 ID 목록을 저장한다. 이는 선택한 구현 설계이지 기존 실험 결과가 아니다.

- Train 70%: 모델 학습, 환자 단위 5-Fold CV로 하이퍼파라미터 선택.
- Validation 15%: 환자 단위로 다시 V_cal과 V_select로 나눈다. V_cal은 보정기 fit, V_select는 보정 방법·경보 임계값 선택과 비교에 사용한다. 비율은 1:1을 시작안으로 하고 양성 환자 수를 기록한다.
- Test 15%: 모든 모델·가중치·보정·임계값을 고정한 뒤 최종 평가. 성능을 보고 재튜닝하지 않는다.

A+B 병합에서는 B도 학습에 참여하므로 B를 외부 검증이라고 부르지 않는다. 별도 병원 이동 실험이 필요하면 A 학습/B 평가를 독립 실험으로 정의하고 그 평가 데이터를 튜닝에 사용하지 않는다.

분할은 **특징 생성 전 환자 명단 단계에서 고정**하는 것을 권장한다. 환자 내부의 결정적 창 통계만 먼저 계산하는 것은 가능하지만 전체 데이터로 imputer·scaler·이상값 상한·특징 선택 기준을 학습하면 누수다. 같은 환자의 겹치는 창도 전부 같은 split/fold에 속해야 한다.

5-Fold는 Train 환자 명단을 병원×환자 양성 여부로 층화해서 생성하고 시간 행에 매핑한다. 단순 행 기반 StratifiedGroupKFold는 긴 입원의 영향으로 환자 층화를 정확히 보장하지 않을 수 있으므로 실제 fold 분포를 확인한다. 모든 fold에서 전처리 fit과 조기종료를 해당 fold 내부로 제한한다.

## 7. 모델별 입력과 학습

### XGBoost: 첫 Baseline

- 입력: `(샘플 수, 160)` 통계 특징. 추가 특징은 별도 실험 버전.
- 출력: `SepsisLabel=1` 점수.
- 불균형: 해당 fold 학습 행의 음성/양성 수 비율을 `scale_pos_weight` 시작값으로 사용하고 CV로 조정한다.
- 같은 클래스 가중치를 `sample_weight`와 `scale_pos_weight`에 중복 적용하지 않는다. 환자당 가중치 등 다른 목적의 가중치는 명확히 구분한다.
- 깊이·학습률·트리 수·subsample 등을 Train CV로 선택한다.

### LSTM: 시간 순서 학습

- 기본 값 입력: `(샘플 수, 최대 24시간, 16개 변수)`.
- 권장 추가 채널: 변수별 측정 여부와 마지막 측정 후 시간. 채택 시 채널 수와 처리 규칙을 명시한다.
- 시각 t까지의 관측만 사용. 짧은 창은 실제 길이 기반 packed sequence 또는 동등한 길이 처리로 패딩을 제외한다. 미래 기록으로 채우지 않는다.
- 마지막 실제 시점의 출력으로 y[t]를 예측한다. 양방향 모델로 창 밖 미래를 사용하는 구성은 금지한다.
- 기본 손실: BCEWithLogitsLoss의 pos_weight. Focal Loss는 별도 비교이며 처음부터 함께 적용하지 않는다.
- 대치·스케일링·배치 구성·조기종료는 환자 split과 fold 경계를 지킨다.

### Soft Voting

동일한 환자·시각의 확률을 결합한다. 로짓을 확률처럼 평균하지 않는다.

`p_ensemble = w × p_xgb + (1−w) × p_lstm`

w=0.5를 시작점으로 두고 가중치 후보는 Train의 OOF 예측으로 비교한다. 이후 기본 모델은 Train 전체로 재학습한다. Test로 가중치를 선택하지 않는다. 앙상블이 단일 모델보다 나쁘면 결과를 그대로 보고하며 서비스 모델 선택과 과제의 앙상블 구현 요구를 구분한다.

## 8. Calibration과 경보

1. Train CV/OOF로 기본 모델과 앙상블 가중치 고정.
2. Train 전체로 기본 모델 재학습.
3. V_cal의 **자연 양성 비율**에서 최종 출력의 보정기 fit.
4. V_select에서 Platt/Isotonic을 비교하고 보정 방법 및 두 경보 임계값 선택.
5. 선택 이후 보정기를 다른 데이터로 재학습하지 않고 Test 평가.

Platt Scaling을 우선 비교한다. Isotonic은 양성 샘플이 적을 때 과적합할 수 있다. 클래스 가중치가 적용된 학습 점수를 그대로 실제 위험 확률이라고 표시하지 않는다.

정상: p<T_warning, Warning: T_warning≤p<T_alert, Alert: p≥T_alert. 두 임계값은 Recall·Precision·공식 Utility·오경보/100 patient-hours·환자당 경보 수를 보고 선택한다. 지속 경보, 재경보 간격, Warning/Alert를 이진 Utility에 매핑하는 규칙도 고정한다. 시간 행 양성 수와 실제 신규 경보 사건 수는 구분한다.

미션에는 0.50/0.75가 명시돼 있으므로 **고정 임계값 결과와 검증으로 최적화한 결과를 모두 보고**한다. 제출 UI에 다른 임계값을 적용할 수 있는지는 과제 기준을 확인한다.

## 9. 평가와 채택 기준

| 지표 | 보고 내용 |
| --- | --- |
| AUROC | 전체 및 A/B별, 목표 ≥0.82 |
| AUPRC | Average Precision을 사용한다고 명시, 목표 ≥0.40 |
| Recall·Precision·Specificity | 선택 임계값 및 0.50/0.75 각각 |
| Sensitivity@95%Specificity | 임계값 선택 절차와 평가 데이터를 명시 |
| PhysioNet Utility | 공식 시간축·라벨·정규화 규칙 사용, 공식 코드와 대조 |
| Brier·ECE | 보정 전후, ECE bin 정의·개수 고정, Brier 목표 ≤0.15 |
| 경보 부담 | 오경보/100 patient-hours, 신규 경보 사건 수, 환자별 탐지율 |
| 조기 발견 | 첫 경보와 공식 발생 시점의 차이, 발생 전 탐지율 |

평가는 학습 가중치나 재표본화를 적용하지 않은 실제 분포에서 수행한다. 시간 행은 독립이 아니므로 신뢰구간은 **환자 단위 bootstrap**으로 구한다. A/B별 지표와 CV 평균·표준편차를 함께 보고한다. Test 비교로 모델을 다시 선택하지 않는다.

Brier≤0.15만으로 충분하다고 판단하면 안 된다. 앞선 분석의 시간 양성률 약 1.80%에서는 모두 0으로 예측해도 Brier가 약 0.018이다. 실제 실행 시 데이터 버전과 현재 양성률을 재확인하고 무정보 기준 모델·Reliability Diagram·AUPRC와 함께 판단한다.

발생 이후 양성 행이 점수를 높일 수 있으므로 공식 전체 시간 평가와 발생 전 조기경보 분석을 구분한다. 임상 진단 정확도나 실병원 일반화가 검증됐다고 주장하지 않는다.

## 10. SHAP, 실험 관리, 서비스

SHAP은 먼저 XGBoost 특징에 적용한다. `Lactate_mean`의 영향은 해당 요약 특징의 기여이지 인과적 원인이나 ‘Lactate 상승’의 직접 증거가 아니다. XGBoost SHAP을 최종 앙상블·보정 확률의 완전한 설명으로 표시하지 않는다. 설명 대상 모델과 출력 공간을 명시한다.

MLflow에 데이터 버전·환자 분할 ID/해시·seed·fold·전처리·특징 목록·가중치·하이퍼파라미터·전체/A/B 지표·보정 방법·임계값·모델 아티팩트를 기록한다. LSTM state_dict와 모델 구조 설정, XGBoost 모델, 보정기, scaler/imputer, 앙상블 가중치를 한 버전으로 묶는다.

서비스 흐름:

`환자 시계열 JSON → 공통 전처리 → 통계 특징/XGBoost + 시퀀스/LSTM → Soft Voting → 보정 → 경보 → FastAPI 응답 → Streamlit`

학습과 API는 같은 전처리·특징 함수를 사용한다. API 모델은 시작 시 한 번 로드하며 대시보드는 모델을 직접 읽지 않는다. `/health`, `/predict`, `/predict_batch`, `/explain`과 입력 단위·결측·시간 순서 검증을 구현한다. 지연은 CPU 조건, 24h 입력, batch=1, 10회 워밍업 후 100회 평균/P95를 기록한다.

## 11. 구현 순서와 검증 완료 기준

1. 로더·환자 명단·split/fold 저장: 환자 교집합 0, 병원/양성 분포 확인.
2. 160개 특징 생성: 상수·단일 관측·전체 결측·불규칙 측정 간격·짧은 창을 테스트.
3. 누수 테스트: t 이후 값을 바꿔도 t의 특징 불변, 입력에 라벨 없음, 전처리 fit 환자 추적.
4. XGBoost 5-Fold + 공식 Utility: 첫 재현 가능한 baseline 평가표 생성.
5. LSTM 및 OOF Soft Voting: 같은 샘플·분할로 비교.
6. V_cal 보정/V_select 임계값 선택: 보정 전후 비교와 경보 부담 기록.
7. 설정 고정 후 Test 평가: 최종 모델, 그래프, 보고서 저장.
8. SHAP·API·대시보드: 학습/API 동일 입력 예측 일치, 계약 테스트, 지연 측정.

이 문서는 새 설계 정리이며 제품 코드·설정·원본 미션을 변경하지 않는다. 현재 작업 트리에서 삭제된 기존 분석 문서는 복구하거나 덮어쓰지 않았다.
